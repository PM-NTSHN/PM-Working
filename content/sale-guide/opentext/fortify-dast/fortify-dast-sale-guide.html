01
Giới thiệu OpenText & Giải pháp DAST
🏢 OpenText là ai?
  • Tập đoàn phần mềm doanh nghiệp hàng đầu thế giới (Canada), chuyên về quản lý thông tin và an ninh mạng
  • Thương hiệu Fortify được OpenText mua lại từ Micro Focus, kế thừa từ HP Fortify — hơn 20 năm phát triển
  • Được xếp hạng Leader liên tiếp 10+ năm trên Gartner Magic Quadrant về Application Security Testing (AST)
  • Khách hàng: Fortune 500, ngân hàng, bộ quốc phòng, viễn thông toàn cầu
🔍 DAST là gì?

Dynamic Application Security Testing (DAST) — Kiểm thử bảo mật ứng dụng động — là phương pháp tấn công thử nghiệm vào ứng dụng đang chạy thực tế để tìm ra lỗ hổng.

  • Mô phỏng hacker tấn công từ bên ngoài vào web app, API
  • Không cần mã nguồn — chỉ cần URL của ứng dụng
  • Phát hiện lỗ hổng runtime: SQL Injection, XSS, Auth bypass...
  • Fortify DAST gồm: WebInspect + ScanCentral DAST
Điểm khác biệt DAST vs SAST: SAST quét mã nguồn khi đang viết code (bên trong), DAST tấn công ứng dụng khi đã chạy (bên ngoài). Cần cả hai để bảo vệ toàn diện.

02
Vấn đề hiện trạng trong các tổ chức
🎯 Tấn công ngày càng tinh vi
  • Web app và API là mục tiêu tấn công số 1 hiện nay
  • OWASP Top 10 vẫn còn phổ biến: SQLi, XSS, IDOR, XXE...
  • API "bóng tối" (shadow API) không được biết đến = nguy cơ ẩn
🔓 Kiểm tra bảo mật còn thủ công
  • Pentest định kỳ 1-2 lần/năm — không đủ tần suất
  • Pentester thiếu — chi phí cao, thời gian lâu
  • Không có quy trình tự động hóa trong DevSecOps
📉 Hệ quả kinh doanh
  • Lộ dữ liệu khách hàng → phạt PDPA, mất uy tín
  • Downtime → thiệt hại doanh thu trực tiếp
  • Chi phí fix sau triển khai cao hơn 30× so với phát hiện sớm
Câu hỏi đặt ra cho khách hàng: "Hiện tại tổ chức của bạn kiểm tra bảo mật các ứng dụng web/API bao lâu một lần? Quy trình đó tự động hay thủ công?"

03
Tính năng nổi bật của Fortify DAST
🕷️
Tự động Crawl & Audit
Tự động "bò" toàn bộ ứng dụng web, lập bản đồ cấu trúc, rồi kiểm tra từng điểm dễ bị tấn công. Không cần can thiệp thủ công.
🔌
Quét API toàn diện
Hỗ trợ REST, SOAP, GraphQL, OpenAPI (Swagger 1.0/2.0/3.0), Postman Collection, RAML, WSDL. Tự động khám phá shadow API trong quá trình quét.
🏗️
Hỗ trợ ứng dụng hiện đại
Quét được SPA (Single Page App): Angular, React, Vue. Hỗ trợ HTTP/2, WebSocket, JSON, AJAX, HTML5. Tích hợp Selenium scripts.
🔐
Xác thực tự động
Hỗ trợ OAuth 2.0, Bearer Token, Cookie, HTTP Basic/NTLM. Tự động xử lý đăng nhập SMS OTP, Email OTP. Quản lý session tự động.
🔗
Tích hợp CI/CD
Kết nối Jenkins, Azure DevOps, GitLab CI, Maven, Gradle, MSBuild. Scan tự động mỗi khi build/deploy — bảo mật liên tục trong DevSecOps.
📡
OAST – Phát hiện lỗ hổng ẩn
Out-of-Band Application Security Testing: phát hiện Blind SQLi, Blind XSS, SSRF, XXE qua DNS/HTTP callback. Hỗ trợ cả môi trường air-gapped.
📊
Báo cáo & Dashboard
Dashboard trực quan trên SSC, báo cáo theo chuẩn OWASP, PCI-DSS, HIPAA. Xuất FPR, XML. Ưu tiên lỗ hổng theo mức độ nghiêm trọng.
⚖️
SAST + DAST Correlation
Kết hợp kết quả SAST và DAST trên nền tảng SSC để loại bỏ false positive, ưu tiên chính xác hơn. Không cần agent.
🏭
ScanCentral DAST Farm
Mở rộng theo nhu cầu, triển khai nhiều WebInspect sensor song song. Phù hợp doanh nghiệp lớn có hàng trăm ứng dụng cần quét thường xuyên.
FAST (Functional Application Security Testing): Tích hợp với UFT One, Selenium, Cucumber — chụp traffic từ functional test để tái sử dụng trong DAST scan. Hiệu quả hơn IAST vì vẫn tiếp tục crawl sau khi functional test kết thúc.

Q1 Ứng dụng Tổng số ứng dụng web/API cần quét DAST là bao nhiêu? Xác định số Target/WebInspect license
Q2 Ứng dụng Liệt kê danh sách URL/IP của các ứng dụng cần quét? Xác định cấu hình Single Scan Target hay Concurrent
Q3 API Ứng dụng sử dụng loại API nào? REST, SOAP, GraphQL, gRPC? Chọn module API phù hợp
Q4 API Có file OpenAPI/Swagger, Postman Collection hay WSDL không? Tối ưu cấu hình scan API
Q5 Công nghệ Ứng dụng sử dụng framework gì? (Angular, React, Vue, .NET, Java...) Đảm bảo tương thích, cấu hình SPA scan
Q6 Công nghệ Cơ chế xác thực của ứng dụng? (SSO, OAuth, LDAP, OTP, Basic Auth) Cấu hình authentication cho DAST scan
Q7 Nhân sự Số lượng người thực hiện và xem kết quả DAST scan là bao nhiêu? Tính số lượng Fortify User license
Q8 Nhân sự Số scan song song tối đa cần thực hiện cùng lúc là bao nhiêu? Tính số Concurrent Scan Machine / DAST Sensor
Q9 Triển khai Hạ tầng triển khai: On-premise, Private Cloud, hay Hybrid? Lựa chọn mô hình triển khai phù hợp
Q10 Triển khai Môi trường mạng: Internet-facing hay internal (air-gapped)? Cấu hình OAST server (public vs private)
Q11 CI/CD Có quy trình CI/CD không? Dùng Jenkins, GitLab CI, Azure DevOps? Tích hợp DAST vào pipeline tự động
Q12 CI/CD Tần suất quét mong muốn: hàng ngày, hàng tuần, hay theo trigger? Sizing server, lập kế hoạch license
Q13 Tuân thủ Tổ chức cần tuân thủ chuẩn nào? PCI-DSS, ISO 27001, GDPR, TT09? Tùy chỉnh báo cáo theo chuẩn
Q14 Tuân thủ Có yêu cầu lưu trữ lịch sử kết quả scan bao lâu? (1, 3, 5 năm?) Sizing database, storage
Q15 Tích hợp Cần tích hợp kết quả với Jira, Slack, SIEM hay hệ thống khác không? Cấu hình webhook, API integration

Cơ chế tính License
Quan trọng: Fortify DAST tính license theo số lượng người dùng (Users) và số scan engine đồng thời (Scan Machines / Dynamic Engine). Không giới hạn số lần quét hay số IP đích (trừ Single Target License).
Loại License Mô tả Phù hợp với
WebInspect Named User 1 user cố định, cài trên 1 OS, không giới hạn số scan, không giới hạn target Chuyên gia bảo mật cá nhân dùng desktop
WebInspect Concurrent User Nhiều user chia sẻ pool, đếm số người dùng đồng thời. Yêu cầu LIM Server. Không giới hạn scan, target. Đội AppSec có nhiều người dùng luân phiên
WebInspect Single Scan Target Scan không giới hạn số lần vào 1 IP cố định. Cài tối đa 5 máy. Đổi IP 2 lần/12 tháng. Tổ chức chỉ cần quét 1 ứng dụng duy nhất
WebInspect Security Consultant Term License thuê theo thời hạn (1 tháng / 1 năm), 1 Named User, 1 OS Instance. Dành cho MSP/tư vấn bảo mật. Công ty pentest, tư vấn bảo mật, MSSP
Fortify Concurrent Scanning Model Đếm số scan đang chạy đồng thời (Scan Machine). Cài trên không giới hạn máy. 1 scan = 1 Scan Machine license. Yêu cầu tối thiểu 2 Scan Machines + 1 User. Doanh nghiệp lớn, quét nhiều app song song
Fortify Dynamic Only Scan Machine Chỉ dành cho DAST (WebInspect), không bao gồm SAST. Giá thấp hơn full Concurrent Scan Machine. Chỉ cần DAST, không mua SAST
WebInspect Enterprise Bao gồm toàn bộ tính năng, quản lý tập trung qua SSC. Mỗi user cần có SSC User license. User chỉ request scan không cần license user. Doanh nghiệp enterprise, triển khai ScanCentral DAST
📐 Cách tính đơn giản để lên BOM
  • Số Scan Machine = Số scan DAST chạy đồng thời tối đa
  • Số User = Số người xem/quản lý kết quả trên SSC/WebInspect
  • LIM Server: bắt buộc cho Concurrent User và Concurrent Scan
  • SSC Server: bắt buộc cho WebInspect Enterprise / ScanCentral DAST
  • Database: SQL Server (Microsoft SQL hoặc Oracle)
🖥️ Cấu hình server tham khảo (Viettel)
  • Management Server (SSC): 16 CPU, 32GB RAM
  • ScanCentral DAST Server: 8 CPU, 16GB RAM
  • LIM Server: 4 CPU, 8GB RAM
  • Database Server: 16 CPU, 64GB RAM, SSD
  • DAST Sensor (x5 Windows): 8 CPU, 16GB RAM mỗi node

FAQ – Câu hỏi thường gặp & Trả lời
🔍 Về Sản phẩm & Tính năng
DAST khác gì so với Pentest thủ công? Tại sao cần DAST nếu đã có Pentest? ▼
Pentest thủ công thường thực hiện 1-2 lần/năm, tốn chi phí cao và phụ thuộc vào kỹ năng cá nhân. DAST tự động chạy mỗi khi build/deploy, phát hiện lỗ hổng mới xuất hiện kịp thời. Hai phương pháp bổ sung cho nhau: DAST xử lý "width" (phủ rộng, tần suất cao), Pentest xử lý "depth" (phân tích sâu kịch bản phức tạp). Về lâu dài, DAST giúp giảm scope và chi phí Pentest đáng kể.
Fortify DAST có quét được ứng dụng yêu cầu đăng nhập (authenticated scan) không? ▼
Có. Fortify WebInspect hỗ trợ nhiều cơ chế xác thực: OAuth 2.0, Bearer Token, Cookie-based, HTTP Basic/NTLM, Form-based Login. Ngoài ra hỗ trợ tự động tạo macro đăng nhập và tích hợp Selenium scripts để xử lý luồng xác thực phức tạp bao gồm cả OTP qua SMS/Email.
Fortify DAST phát hiện được những loại lỗ hổng nào? ▼
Fortify DAST phát hiện toàn bộ OWASP Top 10 bao gồm: SQL Injection, Cross-Site Scripting (XSS), Cross-Site Request Forgery (CSRF), Insecure Direct Object Reference (IDOR), XML External Entity (XXE), Security Misconfiguration, Broken Authentication, Sensitive Data Exposure, và nhiều hơn. Với OAST còn phát hiện được Blind SQLi, Blind XSS, SSRF, Remote File Include — những lỗ hổng mà scan thông thường không thể phát hiện.
Thời gian quét một ứng dụng mất bao lâu? ▼
Phụ thuộc vào độ phức tạp của ứng dụng. Ứng dụng nhỏ (~100 trang): 1-2 giờ. Ứng dụng trung bình: 4-8 giờ. Ứng dụng lớn có nhiều API: 12-24 giờ. Fortify hỗ trợ Incremental Scan — chỉ quét phần thay đổi so với scan trước, giúp rút ngắn thời gian đáng kể trong CI/CD pipeline.
🔑 Về License & Sizing
License DAST tính theo số ứng dụng hay số người dùng? ▼
Fortify DAST không tính theo số ứng dụng hay số lần quét. License được tính theo: (1) Số Scan Machine đồng thời — số scan chạy song song tối đa, và (2) Số User — người dùng truy cập SSC/WebInspect để xem/quản lý kết quả. Ví dụ: nếu bạn cần chạy 3 scan cùng lúc → cần 3 Dynamic Scan Machine + số user tương ứng.
Khách hàng nhỏ chỉ có 1-2 ứng dụng web nên mua loại license nào? ▼
Với khách hàng nhỏ: WebInspect Named User License (1 người dùng, không giới hạn target, không giới hạn số lần scan) hoặc WebInspect Single Scan Target (chỉ cần quét 1 IP/domain cố định, chi phí thấp hơn). Với công ty tư vấn bảo mật muốn dùng cho nhiều khách hàng: Security Consultant Term License (thuê theo tháng/năm).
Cần bao nhiêu server để triển khai Fortify DAST cho doanh nghiệp vừa (~20 ứng dụng)? ▼
Cấu hình tối thiểu gợi ý: 1 Management Server (SSC + ScanCentral DAST, 8-16 CPU, 32GB RAM), 1 LIM Server (4 CPU, 8GB RAM), 1 Database Server (SQL Server, 8 CPU, 32GB RAM), và 2-3 DAST Sensor (Windows Server, 8 CPU, 16GB RAM mỗi node). Tổng: khoảng 5-6 VM. Có thể consolidate nếu cấu hình phần cứng đủ mạnh.
🚀 Về Triển khai
Fortify DAST có triển khai được trong môi trường mạng nội bộ (không có Internet) không? ▼
Hoàn toàn có. Fortify DAST được thiết kế để triển khai fully on-premise. Đặc biệt, tính năng OAST Private Docker Container cho phép phát hiện blind attacks (Blind SQLi, Blind XSS, SSRF) ngay cả trong môi trường air-gapped, không cần kết nối ra Internet. Đây là điểm mạnh khi bán cho Công an, Quân đội, Bộ ngành nhạy cảm.
Thời gian triển khai Fortify DAST từ đầu đến khi vận hành được mất bao lâu? ▼
Theo OpenText, ScanCentral DAST có thể "up and running in one hour" với Docker container. Thực tế triển khai doanh nghiệp đầy đủ (on-premise, cấu hình LIM, SSC, sensor pool, tích hợp CI/CD): 3-5 ngày cho kỹ sư triển khai. Sau đó cần 1-2 tuần training và pilot scan đầu tiên. Tổng dự án triển khai đầy đủ: 4-6 tuần.
Fortify DAST có tích hợp được với GitLab và Jenkins không? ▼
Có. Fortify cung cấp plugin và REST API để tích hợp với Jenkins (Fortify Jenkins Plugin), Azure DevOps, GitLab CI, Bamboo, Maven, Gradle, MSBuild. Quy trình: developer push code → CI/CD trigger build → Fortify DAST tự động scan staging environment → kết quả trả về SSC → notify qua Jira/email/Slack nếu phát hiện lỗ hổng nghiêm trọng.

Burp phù hợp pentest cá nhân; Fortify phù hợp enterprise DevSecOps.
