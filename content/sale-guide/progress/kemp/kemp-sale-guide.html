🎯 ADC là gì? Giải thích đơn giản cho khách hàng
Định nghĩa đơn giản: ADC (Application Delivery Controller) là thiết bị/phần mềm đứng giữa người dùng và hệ thống máy chủ, phân phối tải thông minh, bảo mật ứng dụng, và đảm bảo dịch vụ luôn hoạt động liên tục.
  • SLB (Server Load Balancing): Chia đều traffic đến nhiều server – tránh quá tải 1 server
  • VIP/VS: Một địa chỉ IP đại diện cho toàn bộ cụm server phía sau
  • Real Server (RS): Các server thật đứng sau ADC xử lý request
  • SSL Offload: LoadMaster xử lý mã hóa/giải mã TLS thay vì server – giảm tải CPU
  • WAF: Tường lửa ứng dụng web – chặn tấn công SQL injection, XSS…

Server quá tải, downtime thường xuyên

Chỉ có 1–2 server xử lý toàn bộ traffic. Khi cao điểm (khai trường, nộp hồ sơ, đầu tháng lương...) hệ thống sập, người dùng không truy cập được.

🔓

Ứng dụng web bị tấn công liên tục

Website, cổng dịch vụ công, hệ thống nội bộ bị SQL injection, XSS, DDoS. Mất dữ liệu, bị deface, ảnh hưởng uy tín tổ chức.

🐢

Hiệu năng SSL/TLS kém

Máy chủ phải tự xử lý mã hóa HTTPS làm tiêu tốn 30-40% CPU. Khi nhiều kết nối SSL đồng thời, response time tăng vọt.

🌍

Hệ thống phân tán, thiếu GSLB

Data center ở nhiều tỉnh/vùng nhưng không có cơ chế điều hướng thông minh. Một DC sập là người dùng toàn vùng mất truy cập.

🔑

Xác thực phân tán, không đồng bộ

Người dùng phải đăng nhập nhiều lần khi dùng nhiều ứng dụng. Thiếu SSO, không tích hợp được Active Directory với ứng dụng web.

📊

Thiếu visibility, khó giám sát

Không biết traffic phân bổ ra sao, server nào đang quá tải, ứng dụng nào phản hồi chậm. Khi sự cố xảy ra, debug mất rất nhiều thời gian.

⚖️ Server Load Balancing (SLB) – Cân bằng tải L4/L7

Phân phối traffic thông minh đến nhiều server theo nhiều thuật toán, tự động phát hiện server chết và ngừng gửi traffic.

Round Robin Least Connection Weighted RR Source-IP Hash Agent-Based Adaptive Layer 7 Content Switching Chained Failover
Nói với KH: "Hệ thống tự động điều phối traffic, khi 1 server chết – LoadMaster tức thì chuyển sang server khác, user không cảm nhận được gián đoạn."

🛡️ Web Application Firewall (WAF) – Bảo vệ ứng dụng web

Tích hợp WAF đầy đủ, cập nhật threat data hàng ngày, tuân thủ OWASP Top 10 và PCI-DSS Section 6.6.

OWASP Top 10 SQL Injection XSS CSRF Data Loss Prevention Cookie Tampering IP Reputation (daily update) PCI-DSS 6.6
Nói với KH: "WAF tích hợp sẵn trong ADC – không cần mua thêm thiết bị bảo mật riêng, tiết kiệm chi phí và đơn giản hoá hạ tầng."

🔒 SSL/TLS Offload – Giảm tải mã hóa

LoadMaster xử lý toàn bộ SSL/TLS thay máy chủ, hỗ trợ đến 1.000 certificate, FIPS 140-2 Level 1.

TLS 1.0/1.1/1.2/1.3 SNI Support OCSP Validation FIPS 140-2 EV Certificates STARTTLS (POP3/SMTP/IMAP) 1.000 SSL certs
Nói với KH: "Server của bạn không cần xử lý SSL nữa – CPU freed up hoàn toàn cho business logic, tốc độ tăng đáng kể."

🌐 Global Server Load Balancing (GSLB/GEO) – Phân tán địa lý

Điều hướng người dùng đến data center gần nhất/khỏe nhất dựa trên vị trí địa lý, tình trạng server.

Location-Based Routing Round Robin / Chained Failover EDNS Support 256 nodes/FQDN Active/Active HA DNS Health Checking
Nói với KH: "Triển khai DC Hà Nội + HCM, khi Hà Nội sập – user tự động được chuyển về HCM, service 100% uptime."

🔑 Edge Security Pack (ESP) – Xác thực & SSO

Thay thế Microsoft TMG, cung cấp pre-authentication, SSO, 2FA tích hợp với AD/LDAP/RADIUS.

Active Directory / LDAP RADIUS SAML / OIDC Two-Factor Auth Single Sign-On (SSO) X.509 Client Cert Kerberos (KCD) Pre-Authentication
Nói với KH: "Chặn người dùng trái phép ngay tại LoadMaster, không cần request đến server – bảo mật từ lớp đầu tiên."

🚨 IPS & DDoS Mitigation – Phòng chống xâm nhập

Hệ thống IPS tương thích Snort rules, chống DDoS L4/L7 rate-based, ACL, IP Reputation filtering.

Snort-Compatible IPS L4 DDoS Mitigation L7 Rate-Based DDoS IP Allow/Deny List ACL per VS IP Reputation (daily) Botnet Detection
Nói với KH: "Tích hợp IPS với Snort rules – đội SOC có thể import rules tự có, không phụ thuộc vendor cho security updates."

🔴 THÔNG TIN BẮT BUỘC – SIZING & BOM
1
Yêu cầu Throughput cho cân bằng tải ứng dụng là bao nhiêu?
Gợi ý: 1G / 3G / 15G / 25G / 40G? → Quyết định model hardware hoặc virtual. Hỏi cả throughput hiện tại và dự kiến 3-5 năm tới.
2
Triển khai Hardware Appliance hay Virtual (VM)?
Hardware → LoadMaster LM-Xxx-NG. Virtual → VLM trên VMware/Hyper-V/KVM/Cloud (AWS, Azure). Ảnh hưởng đến part number và giá.
3
Số lượng Appliance cần (Hardware/Virtual)?
Thường deploy theo cặp HA (2 thiết bị). Hỏi xem KH muốn Active/Standby hay Active/Active HA.
4
License support bao nhiêu năm?
1 năm hay 3 năm? Enterprise Plus subscription bao gồm WAF + GSLB + 24x7 support. Enterprise chỉ 10x5 và không có WAF.
5
Khách hàng có nhu cầu tính năng nâng cao như WAF, GSLB không?
Nếu có → phải chọn Enterprise Plus subscription. WAF và GSLB không có trong Standard hay Enterprise.
9
Các yêu cầu về performance: Concurrent connection, Total user, SSL TPS, SSL throughput?
SSL TPS quyết định có cần chọn model có SSL acceleration cao hơn không. Concurrent connections ảnh hưởng model hardware. Cần số liệu cụ thể để map vào spec sheet.
🔵 THÔNG TIN BỔ SUNG – GIẢI PHÁP & TRIỂN KHAI
6
Mục tiêu trang bị giải pháp ADC cho hệ thống của khách hàng là gì?
High Availability? Tăng performance? Bảo mật ứng dụng? Compliance PCI-DSS? → Giúp định hướng đề xuất đúng tính năng.
7
Hiện trạng hệ thống KH đã sử dụng giải pháp ADC chưa? Nếu có, của hãng nào?
F5 BIG-IP → opportunity to replace/TCO argument. Chưa có → greenfield, cần educate nhiều hơn. Citrix ADC → phân tích migration path.
8
Các tính năng cân bằng tải mà khách hàng yêu cầu cụ thể?
L4 hay L7 load balancing? Content switching? Session persistence? Ghi lại chi tiết để map vào VIP configuration sau.
10
Khách hàng cung cấp Sơ đồ hệ thống để triển khai giải pháp cân bằng tải?
Network topology, IP scheme, số lượng Real Server, ứng dụng nào cần LB → cần thiết cho pre-sales design và sizing chính xác.

📦 Tính năng sản phẩm
KEMP LoadMaster khác gì so với một load balancer thông thường như HAProxy hay Nginx? ▼
KEMP LoadMaster là một Application Delivery Controller (ADC) đầy đủ tính năng, không chỉ là load balancer. So với HAProxy/Nginx miễn phí:
  • WAF tích hợp – HAProxy/Nginx không có, phải ghép thêm ModSecurity
  • SSL Offload chuyên dụng – hiệu năng cao hơn, hỗ trợ FIPS 140-2
  • GSLB/GEO Routing – cân bằng tải giữa nhiều data center
  • ESP/SSO – xác thực tập trung tích hợp Active Directory
  • Support 24x7x365 có SLA rõ ràng, có người chịu trách nhiệm
  • GUI quản lý trực quan – không cần sửa config file thủ công
WAF của KEMP có thực sự hiệu quả không? Cập nhật rules như thế nào? ▼
KEMP WAF dựa trên engine rules công nghiệp, che phủ toàn bộ OWASP Top 10 và các mối đe dọa ứng dụng web hiện đại. Về cập nhật:
  • Cập nhật threat data hàng ngày (với Enterprise Plus subscription)
  • Bao gồm: IP Reputation, Botnet detection, Web malware, WebShell/Backdoor
  • HTTP DoS detection, SQL Injection, XSS, CSRF, Cookie Tampering
  • Tích hợp Snort-compatible IPS rules – team SOC tự import rules được
  • Có thể custom rules theo yêu cầu đặc thù của tổ chức
Lưu ý: WAF chỉ có ở gói Enterprise Plus subscription.
LoadMaster có hỗ trợ GSLB và Disaster Recovery đa data center không? ▼
Có. KEMP GSLB (Global Server Load Balancing) hỗ trợ đầy đủ:
  • Điều hướng DNS-based theo vị trí địa lý, tình trạng server
  • Scale đến 256 nodes per FQDN
  • Hỗ trợ EDNS để định vị client chính xác hơn
  • Các thuật toán: Round Robin, Weighted, Location-Based, Real Server Load, Chained Failover
  • Health check tự động – khi 1 DC sập, DNS tự chuyển về DC khác
  • Active/Active hoặc Active/Passive DR configuration
GSLB cần gói Enterprise Plus subscription.
LoadMaster hỗ trợ những phương thức xác thực nào? Có tích hợp được với AD của chúng tôi không? ▼
LoadMaster hỗ trợ đa dạng phương thức xác thực qua Edge Security Pack (ESP):
  • Active Directory / LDAP – tích hợp trực tiếp với AD domain
  • RADIUS – cho hệ thống 2FA existing
  • SAML 2.0 / OIDC – federation với IdP hiện đại
  • Two-Factor Authentication (2FA) – RSA SecurID, TOTP
  • Kerberos Constrained Delegation (KCD) – SSO Windows native
  • X.509 Client Certificate – xác thực bằng certificate
  • Forms-based Authentication – custom login page
SSO domain cho phép user chỉ login 1 lần, truy cập nhiều ứng dụng.
💻 Triển khai & Vận hành
Mất bao lâu để triển khai LoadMaster? Cần kỹ năng gì? ▼
KEMP được thiết kế để triển khai nhanh:
  • Basic Load Balancing: 2-4 tiếng (cài đặt, cấu hình VIP, Real Servers, health check)
  • Với Application Template (Exchange, SharePoint, RDS...): 30-60 phút là xong
  • HA pair: Thêm 1-2 tiếng để sync config
  • Kỹ năng cần: Network admin cơ bản, không cần chuyên gia F5 hay Citrix cao cấp
  • Giao diện WUI trực quan, có context-sensitive help ngay trên màn hình
So với F5 BIG-IP thường mất 2-5 ngày để cấu hình đầy đủ và cần chuyên gia TMOS.
LoadMaster có thể chạy trên VMware hoặc cloud không? ▼
Có, Virtual LoadMaster (VLM) hỗ trợ đa nền tảng:
  • Hypervisor: VMware vSphere, Microsoft Hyper-V, KVM, Nutanix, XEN, VirtualBox
  • Public Cloud: AWS (BYOL + PAYG), Microsoft Azure (BYOL + PAYG), và các phiên bản Government
  • Cùng giao diện quản lý, cùng tính năng trên tất cả platform
  • Migration dễ dàng: Config từ on-prem → cloud gần như không cần thay đổi
Điểm cộng lớn: team không cần học lại khi migrate workload lên cloud.
HA (High Availability) hoạt động như thế nào? Failover mất bao lâu? ▼
LoadMaster HA hoạt động theo cơ chế Stateful Failover:
  • Stateful Failover: Session table được đồng bộ giữa 2 nodes – user không bị disconnect khi failover
  • Thời gian failover: Mili-giây (dưới 1 giây trong điều kiện bình thường)
  • Modes: Active/Standby (1 active, 1 standby) hoặc Active/Active (cả 2 xử lý traffic)
  • Health monitoring: Tự detect primary fail qua heartbeat
  • Hardware: Hot-Swap PSU và Disk (model từ X15-NG trở lên) – thay PSU không cần tắt máy

KEMP có licensing theo user hay theo throughput? ▼
KEMP license theo throughput (bandwidth), không theo user hay concurrent connection:

  • Virtual: Chọn tier bandwidth (VLM-1G = 1Gbps, VLM-5G = 5Gbps, VLM-MAX = uncapped)
  • Không giới hạn số user, số VIP hay Real Server (tối đa 1.000 VIP và 1.000 RS)
Đây là lợi thế lớn: một license dùng được cho unlimited users và applications, miễn không vượt throughput tối đa.

Tại sao chọn KEMP thay vì F5 BIG-IP mà khách hàng đã biết tên? ▼
3 luận điểm chính:
  • Giá trị tốt hơn: TCO thấp hơn 50-70%, tính năng tương đương cho hầu hết use case. WAF + GSLB + ESP trong 1 subscription; F5 phải mua ASM + GTM + APM riêng.
  • Rating người dùng cao hơn: G2 4.9/5 (97% recommend) vs F5 4.6/5 (86% recommend). Người dùng thực tế đánh giá KEMP dễ dùng và satisfy hơn.
  • Vị trí thị trường: G2 Winter 2025 – KEMP xếp Leader, F5 thấp hơn về satisfaction score.
F5 phù hợp cho tổ chức có yêu cầu rất cao cấp, scripting phức tạp (iRules). Với 90% use case điển hình – KEMP đủ sức và kinh tế hơn.
KEMP có thể replace Microsoft TMG không? ▼
Có. Đây là một điểm mạnh rõ ràng của KEMP – Edge Security Pack (ESP) được thiết kế để thay thế Microsoft Forefront TMG (đã end-of-life từ 2012):
  • Pre-authentication cho các ứng dụng published ra Internet
  • Reverse proxy với SSL bridging
  • Active Directory / Kerberos authentication
  • Forms-based authentication
  • SSO qua nhiều published applications
  • SMTP domain filtering
Nhiều tổ chức vẫn dùng TMG hoặc giải pháp self-built thay thế – đây là cơ hội bán KEMP với ESP.

KEMP có đạt chứng chỉ bảo mật quốc tế nào không? ▼
Có, LoadMaster đạt nhiều chứng chỉ quan trọng:
  • FIPS 140-2 Level 1 – tiêu chuẩn mã hóa của Chính phủ Mỹ (dùng SSL/TLS)
  • Common Criteria (ISO/IEC 15408) – chứng nhận bảo mật quốc tế
  • USGv6 Certified – chuẩn IPv6 của US Government
  • PCI-DSS Section 6.6 Compliance – WAF đáp ứng yêu cầu thanh toán thẻ
Với tổ chức chính phủ hoặc ngân hàng cần compliance – KEMP đáp ứng được mà không cần add-on.
DDoS mitigation của KEMP hoạt động như thế nào? Chặn được ở cấp độ nào? ▼
KEMP LoadMaster có DDoS mitigation đa lớp:
  • Layer 4 DDoS: SYN flood, UDP flood – chặn tại transport layer
  • Layer 7 DDoS: HTTP flood, Slowloris, rate-based L7 attacks
  • IP Reputation: Tự động block IP độc hại được cập nhật hàng ngày
  • Rate Limiting: Giới hạn số request per second per IP hoặc global
  • ACL (Access Control List): Allow/Deny theo IP, subnet, geo
  • IPS (Snort Rules): Detect và block attack patterns
Lưu ý: Với volumetric DDoS quy mô lớn (Gbps), vẫn cần upstream ISP-level scrubbing kết hợp. KEMP xử lý tốt application-layer DDoS và targeted attacks.
📐 Sizing & BOM
Làm thế nào để chọn đúng model cho khách hàng? ▼
Quy trình sizing đơn giản 3 bước:

Bước 1 – Xác định throughput: Hỏi bandwidth Internet hiện tại và dự kiến. Rule of thumb: chọn model có throughput ít nhất = 2x Internet bandwidth hiện tại.

Bước 2 – Kiểm tra SSL TPS: Hỏi số concurrent HTTPS sessions. Nếu >10,000 SSL TPS – cần model X25-NG trở lên.

Bước 3 – Xác nhận tính năng: Cần WAF/GSLB → Enterprise Plus. Chỉ cần SSO → Enterprise. Cơ bản → Standard.

Reference nhanh:
  • Sở/Ban nhỏ: LM-X3-NG + ENP
  • Bộ/Tỉnh lớn: LM-X15-NG + ENP
  • Doanh nghiệp vừa: VLM-5G hoặc LM-X15-NG
  • Ngân hàng, DC lớn: LM-X25-NG trở lên
Có cần SFP module không? Khi nào thì cần? ▼
SFP module cần khi kết nối uplink qua cáp quang (fiber):
  • Kết nối 10GbE qua fiber: Cần SFP+ transceiver (ví dụ X15-NG-SFP-SR cho SR 850nm, tối đa 300m)
  • Kết nối 10GbE qua DAC/Direct Attach Cable: Không cần SFP riêng
  • Kết nối 1GbE RJ45: Không cần SFP
Hỏi KH: Switch uplink là loại nào? Nếu dùng fiber SFP+ port trên switch → cần quote SFP module tương ứng theo distance (SR 300m, LR 10km...). Bundle X15-NG-SFP-SR gồm 4 transceivers.
